# Hirz P1 — Live Core Implementation Plan

> **ملخص بالعربية:** المرحلة P1 تبني أول نسخة **تعمل فعلًا**، وتتكون من ثلاثة أجزاء:
> - **الخادم (Core):** حسابات ودوائر ودعوات، وأصول واقتران بالمرافق، وأماكن، واستقبال الإشارات، ومحرك قواعد أول (SOS، الخروج المؤكد من مكان، الصمت)، وحوادث، وإشعارات FCM مع إيصالات الوصول والفتح.
> - **التطبيق:** وضع الولي (خريطة، أماكن، دائرة، حوادث، إنذار بشاشة كاملة)، ووضع المرافق (اقتران، موقع ونبض في الخلفية، SOS، رمز إكراه، رد على Check-in).
>
> **بوابة الخروج:** ضغط SOS على هاتف المرافق يُظهر إنذارًا بشاشة كاملة على هاتف الولي، ويُقاس زمن الوصول على 10 تجارب.
>
> **قبل البدء تلزمك أشياء لا أستطيع فعلها نيابة عنك** (Task 0).

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A companion phone's SOS or a confirmed place exit reaches every guardian's phone as a full-screen alarm, through Hirz Core, with sent/delivered/opened receipts and a measured latency.

**Architecture:**
- **Hirz Core** (Ktor/JVM):
  - PostgreSQL + PostGIS through Exposed and Flyway.
  - Firebase Auth ID tokens for members, and opaque bearer tokens for sources.
  - A pure rules engine fed by an ingest pipeline.
  - An incident service that fans out to all members in parallel through a `Notifier` (FCM HTTP v1).
  - A WebSocket live channel.
- **The app** (Compose Multiplatform, Android target) talks to Core through a typed Ktor client. API DTOs live in `:shared`, so client and server share one contract.
- Traccar is **not** in the P1 data path. The companion speaks HTTPS to Core, and device ingestion through Traccar is P3.

**Tech Stack:**
- Additions to P0: Exposed, HikariCP, Flyway, PostgreSQL JDBC, Testcontainers (`postgis/postgis:16-3.4`), firebase-admin, Ktor auth, websockets and client.
- Android: Firebase Auth + Google Sign-In through Credential Manager, Firebase Messaging, Play Services location, MapLibre Android, zxing-android-embedded, AndroidX DataStore.

**Spec:** `docs/05-hirz-design.md`. The sections that matter here: §1, §2, §3, §4.2–4.3, §5, §6.1–6.5, §7, §8, §9, §10, §12. Phase scope is in §11 P1.

## Global Constraints

- All rules from the P0 plan's Global Constraints still apply: toolchain pins, ar/fr/en with no hard-coded strings, forbidden-claims guard, CI-only Gradle, commit trailer.
- **API DTOs live in `shared/src/commonMain/kotlin/dz/hirz/shared/api/`** and are `@Serializable`. Server and app import them; nobody redefines a DTO.
- **Coordinates are always explicit `{ "lat": …, "lon": … }` objects in the API.** No positional `[x, y]` arrays (v2 WKT/Leaflet lesson). PostGIS stores `geography(…, 4326)`, and the conversion lives in one tested function.
- **Enum wire names follow spec §3** through `@SerialName`:
  - `FixSource`: `gnss`, `wifi`, `cell`, `ble-relay`, `sms`
  - `AlarmKind`: `sos`, `tamper`, `removal`, `powerCut`, `jamming`, `fall`, `duress`
  - `AssetType`: lowercase snake (`child`, `special_needs`, …)
- **Secrets never enter git**, i.e. the Firebase service account and the DB URL. Core reads `HIRZ_DATABASE_URL`, `HIRZ_DATABASE_USER`, `HIRZ_DATABASE_PASSWORD`, `GOOGLE_APPLICATION_CREDENTIALS` and `HIRZ_FIREBASE_PROJECT_ID`. The app's `google-services.json` is git-ignored. CI injects a **fake** configuration instead.
- **Tokens:** source tokens and pairing/invite codes are random. Source tokens are 32 bytes base64url, and pairing codes are 8 chars from an unambiguous alphabet. Only the SHA-256 is stored. Comparison is constant-time.
- **Time:** the server is the clock of record. All times are epoch milliseconds UTC on the wire. Displayed local time is Africa/Algiers (UTC+1, no DST).
- **Thresholds are starting values to be measured, not truths** (spec §4.3). Each lives in one `RuleConfig` data class with the defaults below:
  - place margin ≥ 50 m (default 50)
  - exit debounce: 3 readings
  - re-entry: 2 readings inside `radius − 15 m` hysteresis
  - reading accepted for boundary rules only if `accuracyM ≤ max(50, marginM)` and age ≤ 120 s
  - impossible jump: > 300 km/h between consecutive fixes
  - silent: heartbeat gap > 5 min → `dead`; heartbeat but no fix > 10 min → `alive`
  - freshness in the UI: fresh < 3 min, stale 3–5 min, silent ≥ 5 min
  - ack windows: P0 60 s, P1 180 s (recorded only; the ladder is P2)
- **Location retention default** is 30 days (spec §8.3). The purge job ships in this phase.
- **Location access log:** every REST/WS read of an asset's position writes `location_views` (spec §12.5.7).
- **No forbidden claims, and no "kidnapping" wording in any P0/P1/P2 notification text.** Alarm texts say what happened ("SOS from Ahmed", "Ahmed left School"), plus the age and the accuracy.

## Review Focus

1. **GPS jitter at a place boundary.** Readings oscillating ±20 m around the edge must not raise `PLACE_EXIT`. Pinned by the replay scenario `boundary_jitter_no_exit` (Task 7).
2. **A late or out-of-order batch from a companion that was offline.** Old fixes must not open a fresh incident or move the "current" position backwards. Pinned by `ingest_out_of_order_keeps_latest` (Task 6) and the replay scenario `offline_backlog_no_new_exit` (Task 7).
3. **A guardian whose FCM token is stale or missing** must not block the delivery to the others. Pinned by `fanout_continues_when_one_token_fails` (Task 8).
4. **The same pairing or invite code used twice, or after expiry**, must be rejected. Pinned by `pairing_code_is_single_use_and_expires` (Task 4) and `invite_is_single_use_and_expires` (Task 3).
5. **A guardian removed from the circle** must lose WS and REST access immediately, including an already-open socket. Pinned by `removed_member_socket_is_closed` (Task 9).

### Task 7: Rules engine v0 and replay harness

**Files:** `server/.../rules/*`, `server/.../jobs/SilenceScanner.kt`, `rules/ReplayTest.kt`, `server/src/test/resources/scenarios/*.json`.

**Interfaces — Produces:**
- `data class Finding(val assetId: UUID, val rule: RuleId, val tier: Tier, val reasons: List<Reason>, val at: Instant, val silent: Boolean = false)`
- `enum class RuleId { SOS, DURESS, PLACE_EXIT, SILENT_SOURCE }`
- `enum class Tier { P0, P1, P2 }`
- `@Serializable data class Reason(val code: String, val args: Map<String,String>)`. Codes are rendered client-side through i18n, e.g. `left_place{place, at, readings, accuracyM, ageS}`.
- `interface Rule { fun evaluate(ctx: RuleContext): List<Finding> }`
- `RuleContext(signal, asset, places, state: AssetState, config: RuleConfig, now: Instant)`. `AssetState` holds the per-(asset, place) inside/outside status and the counters.
- `class RulesEngine(rules: List<Rule>, stateStore: AssetStateStore)` implements `RulesSink`. State is persisted in table `asset_rule_state`, added as `V2__rule_state.sql`.
- Rules:
  - **SosRule:** `SOS` → P0. `DURESS` → P0 with `silent = true`.
  - **PlaceExitRule:**
    - Only active places of kind ≠ forbidden/hazard. A **forbidden or hazard place raises the finding on entry**, with the same debounce.
    - Uses only readings that are accepted (accuracy and age gates) and not jump-flagged.
    - **Exit** = 3 consecutive accepted readings with `distanceOutsideM > marginM`.
    - **Re-entry** = 2 consecutive readings inside `radius − 15 m` (circle) or `≥ 15 m` inside the polygon edge.
    - Only fires on an inside→outside transition, never at startup when the first known state is outside.
    - Readings with a fix time older than the state's last evaluated fix are ignored.
  - **SilentSourceRule:** run by `SilenceScanner` every 30 s over sources. The heartbeat gap > 5 min gives P2 `SILENT_SOURCE{mode=dead}`. Heartbeat present but no fix > 10 min gives P2 `{mode=alive}`. **If the asset has an open P0/P1 incident, it adds the reason `silence_during_incident` to that incident instead** (Task 8 API).
- **Replay format:** `{ "asset": {...}, "places": [...], "signals": [{ "t": "+0s", "lat":…, "lon":…, "acc":…, "alarms": [] }], "expect": [{ "rule": "PLACE_EXIT", "tier": "P1", "atSignal": 5 }] }`.
