# Hirz P3 — Devices and Staging Implementation Plan

> **ملخص بالعربية:** المرحلة P3 تُدخل **أجهزة التتبع الحقيقية** وتضع الخادم على **عنوان عام**:
> - **Traccar يمرّر كل موقع وحدث إلى Core** (`forward.url` و`event.forward.url` بسرّ مشترك)، و**مطابِق** يحوّل صيغة Traccar إلى عقد الإشارة نفسه.
> - **إضافة متتبع بإثبات حيازة:** لا يُفعَّل IMEI إلا إذا وصل منه موقع **بعد** طلب الإضافة، أي أن المضيف غيّر خادم الجهاز بنفسه. معرفة IMEI سيارة غيرك لا تكفي.
> - **كتالوج الطرازات** (مُختبَر / مدعوم / مرفوض) مع **ورقة أوامر SMS لكل طراز**.
> - **معالج داخل التطبيق:** اختر الطراز، فيُجهّز رسائل الإعداد ويفتحها في تطبيق الرسائل، ثم ينتظر أول إشارة، ويعرض ما يدعمه الجهاز وما لا يدعمه.
> - **staging عام** على Oracle Cloud المجاني (Core + Traccar + Caddy/HTTPS)، وصورة Core تُبنى في CI.
> - **اختبار شامل في CI:** محاكي GT06 ← Traccar ← Core ← حادث، بلا هاتف.
> - **الدَّين المحمول من P2:** تنبيهات الحضانة المشتركة للدائرة الثانية، والحفظ على أندرويد 8–9.
>
> **بوابة الخروج:** AC-1 على شبكة الجوال (موقع المتتبع يظهر عند الولي خلال 30 ث p95)، وورقة أوامر SMS مُثبتة لكل طراز اشتريناه.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A real GSM tracker, configured by its owner from the app, reports through Traccar into Hirz Core on a public staging server, and its positions and alarms behave exactly like a companion phone's — with proof that the person adding it controls the device.

**Architecture:** Traccar stays a device gateway only (design §2 rule 2). It forwards every position (`forward.url`, JSON) and every event (`event.forward.url`) to two Core endpoints authenticated by a shared secret. A pure `TraccarMapper` turns Traccar JSON into the existing `IngestSignal`, so `IngestService`, the rules and the ladder are unchanged. A `TrackerService` owns the claim lifecycle (pending → active by first report → released) and keeps Traccar's device list in step through its REST API, which also serves as the backup sync. Staging is one ARM VM running Core, Traccar and Caddy in Docker Compose; the database is the existing Supabase project.

**Tech Stack:** P2 stack. New pieces:
- Traccar 6.16.0 `forward.*` / `event.forward.*` and its REST API (`/api/devices`, `/api/positions`);
- Docker (Core image `eclipse-temurin:21-jre`, multi-arch via `docker buildx`), GitHub Container Registry `ghcr.io/toufikben/hirz-core`;
- Caddy 2 for HTTPS (automatic Let's Encrypt);
- Android `Intent.ACTION_SENDTO` with `smsto:` (the Play build still declares no SMS permission).

**Spec:** `docs/05-hirz-design.md` §2 (rules 2–3), §3 (contract, support levels, wizard), §8.2 (Traccar hardening), §9 (staging), §10 (AC-1, latency), §11 (P3 row), §12.5.1 (ownership proof), §12.5.8 (used devices). Research: `docs/research/res-traccar.md`, `docs/research/hosting-algeria.md`, `docs/legacy/v2/2026-10-05-parent-side-tracing-design.md` §10–§11 (purchase spec, SMS sheet as the key M3 output). P2 ledger: `.superpowers/sdd/2026-10-29-P2-escalation/progress.md`.

## Global Constraints

- Every P1 and P2 Global Constraint applies unchanged (DTOs in `:shared`, explicit lat/lon, nullable fields default to null, no coordinates or code word in pushes/SMS, RED before GREEN in CI, `test.<uid>` tokens).
- **Traccar** stays pinned at **6.16.0**. `geocoder.enable=false`, `database.registerUnknown=false`, `web.address=127.0.0.1` everywhere except the CI-only override. Only protocols in the catalogue are enabled: **`gt06` (5023), `h02` (5013), `osmand` (5055, internal only)**.
- **Forward secret:** env `HIRZ_TRACCAR_SECRET` (≥ 32 random bytes, base64). Traccar sends it as `Authorization: Bearer <secret>`; Core compares in constant time. Never in the repo; the template carries `${HIRZ_TRACCAR_SECRET}`.
- **Traccar admin credentials** for Core's REST client: env `HIRZ_TRACCAR_URL`, `HIRZ_TRACCAR_USER`, `HIRZ_TRACCAR_PASSWORD`. The Traccar web/API port is never public: staging reaches it over the Docker network only; humans use an SSH tunnel.
- **IMEI:** exactly 15 digits with a valid Luhn check digit. One IMEI is active in at most one circle. The API never says which circle holds an IMEI.
- **Ownership proof (§12.5.1):** a claim becomes active only when Traccar forwards a position from that IMEI whose server time is after the claim was created and within **30 minutes**. Earlier or later reports never activate it. A pending claim expires after 30 minutes and its Traccar device is deleted.
- **Used devices (§12.5.8):** an IMEI active in another circle can be claimed only after that circle's owner releases it. No notice-and-wait takeover.
- **Unit conversion at the edge, once (§3):** Traccar speed is knots → km/h × 1.852; `accuracy = 0` means unknown (estimate it and flag it); `valid=false` or `outdated=true` is a heartbeat without position.
- **Staging DB** is the existing Supabase project (PostGIS on). The VM runs no database. Core reads secrets from `/opt/hirz/core.env` (mode 600), never from the compose file.
- **Device support levels:** `CERTIFIED` only after the device trial (Task 9) proves the model's SMS sheet on its exact firmware; until then a model is `SUPPORTED` with the warning "not tested". `REJECTED` models (vendor-locked kids' watches, 2G-only after shutdown dates) are listed with the reason.

## Out of P3 (deliberate)

- **Teltonika** (Codec 8) and **satellite** devices: no unit to test; `SUPPORTED` entries come with the device that needs them (P4/P6).
- **Identification port 5001 / `saveOriginal`** for unknown models: an operator procedure in the runbook, not an app feature. The wizard's "I don't know my model" path tells the owner to send the model photo to support.
- **Remote fuel cut** and other Traccar commands to devices: P4 (vehicles), with its own safety gates.
- **prod** hosting, synthetic heartbeat monitoring, off-site backups: before the first real family (P8). Staging gets a nightly Supabase export only (Task 6).
- **HMS push / non-Google phones:** later; FCM only.

## Review Focus

1. **Traccar retries a forward it already delivered** (forward retry after a slow 2xx) → exactly one stored position and no second finding. Pinned by `retriedForwardIsStoredOnce` (Task 2).
2. **A position from an IMEI that is not claimed, or whose claim expired** → nothing stored, no source created, one log line. Pinned by `unknownImeiIsDropped` and `expiredClaimNeverActivates` (Task 2).
3. **A tracker reconnects after hours and uploads its buffer** → every fix stored as history, no place exit raised for old fixes, the newest one evaluated. Pinned by `bufferedBacklogIsHistoryOnly` (Task 2).
4. **GT06 heartbeat packets** arrive as Traccar positions marked `outdated` with the last known coordinates → a heartbeat, never a jump back to an old spot. Pinned by `outdatedPositionIsHeartbeatOnly` (Task 1).
5. **The forward endpoints without the secret, or with a wrong one** → 401, nothing stored. Pinned by `forwardNeedsSecret` (Task 2).
